# Deploy: Vercel + Render + Supabase

```
Browser ──> Vercel (Next.js web app) ──/api/v1 rewrite──> Render (FastAPI, Docker) ──> Supabase Postgres
                                                                   └──> Supabase Storage (design files)
```

- **Vercel** serves the web app. Every `/api/v1/*` request is proxied to the backend
  (`API_URL`), so the browser only ever talks to your Vercel domain: the session cookie
  is first-party and no CORS setup is needed.
- **Render** runs the FastAPI backend from `backend/Dockerfile` as one free web
  service. Background jobs (trend discovery, crawling, AI writing, images) and the trend
  scheduler run inside that process, so no workers, Redis or Render database are needed.
- **Supabase** provides Postgres (with pgvector) and file storage.

Do the steps in this order: database, then storage, then backend, then web app. Each
step needs a value from the one before.

## 1. Supabase: database

1. Create a project at <https://supabase.com/dashboard> (pick the region closest to
   your Render region; the Blueprint uses Frankfurt). Save the **database password**.
2. Get the connection string: project > **Connect** > **Session pooler** (port 5432).
   It looks like
   `postgresql://postgres.<ref>:<password>@aws-0-<region>.pooler.supabase.com:5432/postgres`.
   Use the session pooler, not "Direct connection": the direct host is IPv6-only and
   Render connects over IPv4. Paste it unchanged; the backend converts it and turns on
   TLS itself.
3. Nothing else: the first deploy's migration creates the `vector` extension and all
   tables.

## 2. Supabase: storage for design files

Storage is required on this setup. Render's disk is wiped on every deploy, and Vercel
caps a proxied request at about 4.5 MB, so files must go straight from the browser to a
bucket rather than through the API.

1. **Storage** > **New bucket**, name it `contentpulse`, keep it **private** (the app
   hands out short-lived signed links).
2. **Storage** > **S3 Connection** (project settings): note the **Endpoint**
   (`https://<ref>.supabase.co/storage/v1/s3`) and **Region**, then **New access key**
   and copy the **Access key ID** and **Secret access key** (shown once).
3. Uploads go straight from the browser to storage through a signed link. After the
   first deploy, try one upload on a design task. If the browser blocks it, use
   Cloudflare R2 instead (same five settings; add a CORS rule allowing `PUT` and `GET`
   from your Vercel domain).

## 3. Render: backend

1. Push this repository to GitHub (it already has `origin`).
2. <https://dashboard.render.com> > **New** > **Blueprint** > pick the repository.
   Render reads `render.yaml` and asks for every value marked `sync: false`:

   | Variable | Value | Where it comes from |
   |---|---|---|
   | `DATABASE_URL` | the session pooler URL | Supabase step 1 |
   | `FRONTEND_URL` | `https://<project>.vercel.app` | Vercel (step 4). Put a placeholder now, fix it after step 4 |
   | `CORS_ORIGINS` | `["https://<project>.vercel.app"]` | same as above, as a JSON list |
   | `S3_BUCKET` | `contentpulse` | Supabase step 2 |
   | `S3_ENDPOINT_URL` | `https://<ref>.supabase.co/storage/v1/s3` | Supabase step 2 |
   | `AWS_REGION` | e.g. `eu-central-1` | Supabase step 2 |
   | `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY` | the storage access key | Supabase step 2 |
   | `LLM_PROVIDER` | e.g. `gemini` (or leave empty for rules and templates) | your choice |
   | `GEMINI_API_KEY` | AI key | <https://aistudio.google.com/apikey> |
   | `GROQ_API_KEY` | optional fallback model | <https://console.groq.com/keys> |
   | `EMBEDDING_PROVIDER` | `gemini` (or empty) | uses the Gemini key |
   | `IMAGE_PROVIDER` | `kie` (or empty to hide AI images) | your choice |
   | `KIE_AI_API_KEY` | image key | <https://kie.ai/api-key> |
   | `CLOUDFLARE_ACCOUNT_ID`, `CLOUDFLARE_API_TOKEN` | free daily image allowance (alternative or backup to Kie) | Cloudflare dashboard: the account id is on the Workers AI page; **My Profile > API Tokens > Create Token** with the "Workers AI" template |
   | `SMTP_HOST`, `SMTP_USERNAME`, `SMTP_PASSWORD`, `SMTP_FROM` | optional email | your mail provider (Resend, Postmark, SendGrid, Amazon SES, Gmail app password) |

   | `AUTH_PROVIDER` | `local` (email + password) or `supabase` | your choice; empty means `local` |
   | `SUPABASE_URL`, `SUPABASE_ANON_KEY` | only for `supabase` sign-in | Supabase > project > **API Keys** |

   Leave optional values empty; the app runs without them. `JWT_SECRET` is generated by
   Render. `APP_ENV`, `TRUSTED_PROXY_COUNT`, the job and rate-limit backends are preset. Any other variable from `.env.example` (Anthropic,
   OpenAI, Cerebras, Cloudflare images, NewsAPI, X…) can be added later under the
   service's **Environment** tab.
3. **Apply**. No payment method is needed: the Blueprint creates a single **free** web
   service. The first deploy builds the image, then runs `alembic upgrade head` and
   starts the API. When it's live, open
   `https://<service>.onrender.com/health`; it should answer `{"status": "ok"}`.
   Copy that base URL (without `/health`).

The free plan sleeps after 15 minutes without traffic and takes about a minute to wake,
so the first request after a quiet spell is slow, and scheduled trend discovery only
runs while it's awake. For real use, change `plan: free` to `plan: starter` in
`render.yaml` (about $7/month, always on); you can then also move migrations to
`preDeployCommand: alembic upgrade head`.

## 4. Vercel: web app

1. <https://vercel.com/new> > import the same GitHub repository.
2. **Root Directory**: `frontend`. The framework (Next.js) is detected automatically.
3. **Environment Variables**:

   | Variable | Value |
   |---|---|
   | `API_URL` | the Render URL from step 3, e.g. `https://contentpulse-api.onrender.com` |

   That is the only one. The web app reads everything else (sign-in mode, Supabase
   keys if you use Supabase Auth) from the backend at runtime. The build fails on
   purpose if `API_URL` is missing.
4. **Deploy**, then copy the production URL (`https://<project>.vercel.app`, or your
   own domain under **Settings > Domains**).
5. Back in Render, set `FRONTEND_URL` and `CORS_ORIGINS` to that URL and save (Render
   redeploys). Invitation and password-reset links use `FRONTEND_URL`.

## 5. Check it

1. Open the Vercel URL: the landing page loads.
2. **Start free**, create an account and an organization.
3. Trends > run discovery: items arrive within a minute or two.
4. Write a post, open its design task and upload an image (this tests storage).
5. Render > Logs should show no errors.

## Optional

- **Supabase Auth instead of email + password**: set `AUTH_PROVIDER=supabase`,
  `SUPABASE_URL` (`https://<ref>.supabase.co`) and `SUPABASE_ANON_KEY` (project >
  **API Keys** > publishable key) on Render. In Supabase > Authentication > URL
  Configuration, set the Site URL to your Vercel URL and add
  `<Vercel URL>/auth/callback` as a redirect URL. Supabase then sends reset emails itself.
- **Redis** (only for more than one backend instance): an Upstash Redis URL in
  `REDIS_URL`, with `RATE_LIMIT_BACKEND=redis` and `LLM_LIMITER_BACKEND=redis`.
- **Custom domain**: add it in Vercel, then update `FRONTEND_URL` and `CORS_ORIGINS`.

## Security

- Never commit `.env`. Use new API keys for production rather than your development
  keys, and rotate any key that was shared (see `docs/production.md`).
- The backend's own URL (`onrender.com`) is public but only needed by Vercel. Sign-in
  cookies are set for the Vercel domain.
